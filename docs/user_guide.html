Розділ 02

Початок роботи

Як зараз працює застосунок

Окремого веб-інтерфейсу (frontend) ще немає — це заплановано на одну з наступних ітерацій (React SPA, див. беклог). Наразі магазин доступний як REST API, і взаємодіяти з ним можна через:

🧪 Swagger / PostmanРучні запити до ендпоінтів API.
💻 curl / HTTP-клієнтКомандний рядок або будь-який REST-клієнт.
🗄️ SQL Server LocalDBБаза створюється автоматично при першому запуску.
⚙️ .NET 9Потрібен встановлений SDK для запуску проєкту.

Запуск проєкту

  1. Клонуйте репозиторій: git clone https://github.com/vicitmceo/NewBalanceShop.git
  2. Перевірте рядок підключення в appsettings.json (ConnectionStrings:ShopDb).
  3. Виконайте dotnet run — база та тестові дані створяться автоматично.
  4. Відкрийте https://localhost:PORT/api/products, щоб побачити каталог.
Розділ 03

Ролі користувачів

Відповідно до SRS, у системі передбачені такі ролі:

  • Гість — перегляд каталогу, фільтрація, перегляд картки товару.
  • Покупець — кошик, оформлення замовлення, історія замовлень (реєстрація/авторизація — у беклозі, ще не реалізовано).
  • Адміністратор — CRUD товарів і категорій, перегляд замовлень (наразі доступ до CRUD не обмежений — авторизація в планах).
⚠️ Поточний стан: у цій версії немає розмежування доступу за ролями — усі ендпоінти відкриті. Розмежування зʼявиться разом із реєстрацією/авторизацією (ASP.NET Core Identity) у наступному спринті.
Розділ 04

Каталог товарів

Перегляд усіх товарів

Запит GET /api/products повертає список усіх товарів у форматі JSON: назва, бренд, категорія, розмір, колір, ціна, залишок на складі, зображення, опис.

Фільтрація за категорією

Додайте параметр categoryId, щоб отримати товари лише однієї категорії, наприклад: GET /api/products?categoryId=1 — усі кросівки.

👟 КросівкиКатегорія Id = 1
👕 ОдягКатегорія Id = 2
🧢 АксесуариКатегорія Id = 3
Розділ 05

Картка товару

Запит GET /api/products/{'{id}'} повертає детальну інформацію про один товар: назву, бренд, розмір, колір, ціну, кількість на складі, посилання на зображення та опис. Якщо товару з таким id не існує — API поверне код 404 Not Found.

Розділ 06

Кошик і оформлення замовлення

⚠️ Заплановано, ще не реалізовано: модель кошика та замовлення (Order, OrderItem) уже описана на рівні Domain-шару, але публічного API для оформлення замовлення поки немає. Це перший пункт наступного спринту (див. беклог).

Як це працюватиме (за планом)

  1. Покупець додає товари в кошик.
  2. Покупець підтверджує кошик і оформлює замовлення.
  3. Система створює Order зі списком OrderItem і розраховує TotalPrice.
  4. Замовлення отримує статус New і зʼявляється в історії покупця.

Статуси замовлення

Передбачені статуси: New → Confirmed → Shipped → Delivered, або Cancelled.

Розділ 07

Адміністрування каталогу

Додавання товару

POST /api/products з тілом запиту у форматі JSON (назва, бренд, категорія, розмір, колір, ціна, залишок, зображення, опис). У відповідь повертається створений товар з присвоєним id.

Оновлення товару

PUT /api/products/{'{id}'} — повністю оновлює дані товару. Якщо товару не існує — 404.

Видалення товару

DELETE /api/products/{'{id}'} — видаляє товар з каталогу.

💡 Порада: усі дані валідуються на рівні моделі (обов'язкові поля, довжина рядків, діапазон ціни та залишку) — при невалідних даних API поверне 400 Bad Request з описом помилок.

Розділ 09

Безпека

Поточний стан

На етапі MVP автентифікація й авторизація не реалізовані — усі ендпоінти доступні без обмежень. Захист від SQL Injection забезпечено параметризованими запитами Entity Framework Core, вхідні дані валідуються через Data Annotations.

Заплановано

  • Реєстрація та авторизація покупців (ASP.NET Core Identity)
  • Розмежування доступу: гість / покупець / адміністратор
  • CI: перевірка збірки та тестів через GitHub Actions
⚠️ Не для продакшену: у поточному вигляді застосунок призначений виключно для навчальних/демонстраційних цілей курсового проєкту.
