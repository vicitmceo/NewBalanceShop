# Доклад: 5 минут (говорит Рафаил, Вадим открывает и закрывает)

Регламент экзамена: доклад 5 минут на всю команду, демо 5 минут, всего не больше 10 минут. Говорим по-русски, слайды на украинском. Файл называется `talk-script-10min.md` по старой привычке, содержание под новый регламент.

В презентации 8 основных слайдов, потом запасные, последний слайд «Ваші питання?». Внизу слайдов есть полоска «Посилання»: ссылки кликабельные. Клик мышью по ссылке открывает её в новой вкладке. Вернуться в презентацию: вернуться на вкладку.

## Вадим: открытие (0:00 – 0:20), слайд 1

«Добрый день. Мы команда Team 1. Наш проект: New Balance Shop, интернет-магазин спортивной обуви и одежды. Нас двое. Я Вадим, тимлид: требования, план, Scrum. Рафаил Ноцколини: весь код, архитектура, деплой. Сначала Рафаил расскажет про проект, потом я буду комментировать демо. Рафаил, пожалуйста».

## Рафаил (0:20 – 4:45)

**Слайд 2. Зачем проект (0:20 – 0:50)**
Проблема простая. Трудно быстро найти и купить нужную пару. Часто заставляют регистрироваться. Корзина пропадает. Наше решение: каталог с фильтрами, корзина, заказ без лишней регистрации, личный кабинет, админ-панель. Аудитория: покупатели 16-40 лет и администратор магазина.

**Слайд 3. Требования и план (0:50 – 1:20)**
Сначала мы написали требования. В SRS 13 функциональных требований. Все 13 сделаны. План работ: 8 спринтов, каждый по одной неделе. Всего пять недель разработки.
[Клик по ссылке «План робіт» в нижней полоске, показать файл плана, вернуться. Затем «SRS», показать файл, вернуться.]

**Слайд 4. Scrum и Jira (1:20 – 2:00)**
Работали по Scrum в Jira. 8 недельных спринтов, 44 задачи, 33 выполнено. Восьмой спринт ещё идёт.
[Клик «Jira»: открыть доску, показать спринт 8, вернуться. Клик «Коміти»: открыть историю коммитов на GitHub, вернуться.]
Честно: у Вадима в Git нет коммитов. Он вёл требования, план, Jira и документы. Весь код написал я. Часть статусов в Jira отстаёт от кода.

**Слайд 5. Архитектура (2:00 – 2:50)**
Фронтенд: React на Vercel. Бэкенд: ASP.NET Core 9 в Docker на Render. База: PostgreSQL на Render. В бэкенде четыре слоя: Web API, Application, Domain, Infrastructure. Domain ни от чего не зависит. Запросы `/api` идут через домен сайта, поэтому сессионная кука работает.
[Клик «Архітектура»: открыть файл ARCHITECTURE.md. Клик «DocFX»: документация кода. Клик «Scalar (API)»: документация API. Клик «README»: README репозитория. После каждого вернуться, не задерживаться дольше 5 секунд.]

**Слайд 6. Живой сайт (2:50 – 3:30)**
Сайт сделан в стиле newbalance.com. 70 товаров, три языка. Фильтры живут в адресе. Есть корзина, оформление без регистрации, кабинет и админ-панель. Есть мобильная версия: в две колонки, без горизонтального скролла. Фото и названия с newbalance.com: это учебный макет. Оплаты нет.
[Клик «Сайт» или «Фронтенд (репо)»: показать репозиторий фронтенда. Живой сайт покажем в демо.]

**Слайд 7. Безопасность, тесты, CI (3:30 – 4:20)**
295 тестов, все зелёные. Покрытие 93,4%. CI в GitHub Actions тоже зелёный. Пароли хранятся как PBKDF2 с солью. Защита от BOLA: покупатель берётся из сессии. Админ-функции защищены ролями: 401 и 403. Сканер ZAP: ноль High. Честные ограничения: сессии в памяти процесса, бесплатная база на Render действует до 18 ноября.
[Клик «README» или «Коміти» только если спросят про цифры.]

**Слайд 8. Ссылки (4:20 – 4:45)**
Все материалы кликабельны: план, SRS, архитектура, Jira, коммиты, README, DocFX, Scalar, фронтенд. Комиссия может открыть любую. Теперь переходим к демо на живом сайте.
[Мышью указать на плитки. Клики не делать, время на исходе.]
