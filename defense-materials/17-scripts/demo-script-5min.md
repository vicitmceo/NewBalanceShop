# Сценарій демо (5 хвилин, 2 клієнтські сценарії)

Усі кроки перевірено на продакшні 11.10.2026. Демо йде через **Swagger UI** (бекенд) і **живий сайт** (фронтенд). Форм реєстрації/логіну та адмін-панелі у React поки немає, тому сценарії показуємо через API.

## Перед демо (за 5 хвилин)

1. Відкрити https://newbalanceshop-api.onrender.com/api/Products: безкоштовний Render «засинає», перший запит може тривати до хвилини.
2. Відкрити в окремих вкладках: https://newbalanceshop.vercel.app і https://newbalanceshop-api.onrender.com/swagger.
3. Мати запасний варіант: скріни з `16-live-ui-screenshots/`.
4. Пароль адміністратора **змінити перед захистом** (зараз він лежить у публічному репозиторії, див. «Безпека» в README).

## Вступ (0:00–0:20)

Показати сайт: каталог із товарами, перемикач мови UA/EN/FR, кошик. Одне речення: «Дані приходять із API на Render, БД PostgreSQL».

## Сценарій 1. Реєстрація й вхід нового користувача (0:20–2:40)

У Swagger UI:

1. `POST /api/Auth/register` → Try it out, тіло:
   ```json
   {
     "fullName": "Demo User",
     "email": "demo.user@example.com",
     "password": "Demo12345!",
     "city": "Kyiv",
     "country": "UA",
     "phone": "+380501112233"
   }
   ```
   Очікується **200**, у відповіді профіль без пароля (`isAdmin: false`).
2. `GET /api/Auth/me` → **200**, повертає того самого користувача: сесійна кука вже встановлена.
3. `POST /api/Auth/logout` → **204**. Знову `GET /api/Auth/me` → **401**.
4. `POST /api/Auth/login` з email і паролем із кроку 1 → **200**, `GET /api/Auth/me` знову **200**.
5. `PUT /api/Customers/{id}` (підставити id зі відповіді), змінити `city` на `Lviv` → **200**: кабінет покупця (FR-10).
6. `GET /api/Customers/{id}/orders` → **200**, історія замовлень (порожня для нового користувача), FR-11.
7. Показати, що звичайний користувач не бачить адмін-функцій: `GET /api/Customers` → **403**.

Що сказати: пароль зберігається як PBKDF2 із сіллю (в БД не відкритий текст), сесія в HttpOnly-куці, вхід також можливий через Google та GitHub.

## Сценарій 2. Адмін-панель для модератора (2:40–4:40)

1. `POST /api/Auth/login` під акаунтом адміністратора (`admin@newbalanceshop.com`, пароль у команди). **200**, `isAdmin: true`.
2. `GET /api/Customers` → **200**, список усіх користувачів (FR-12).
3. Знайти демо-користувача зі сценарію 1. `PATCH /api/Customers/{id}/block` з тілом `{ "blocked": true }` → **200**, `isBlocked: true` (FR-13).
4. Показати наслідок: `POST /api/Auth/login` під демо-користувачем → **401** (обліковий запис заблоковано).
5. `DELETE /api/Customers/{id}` → **204**, користувача видалено. Повторний `GET /api/Customers` більше його не показує.
6. Коротко про товари: на сайті каталог тягнеться з `GET /api/Products`; CRUD товарів доступний у Swagger (POST/PUT/DELETE).

## Завершення (4:40–5:00)

Повернутися на сайт, додати товар у кошик, показати «Мої замовлення». Підсумок: 145 тестів, покриття 86,7%, архітектура з 4 проєктів.

## Якщо щось пішло не так

- API довго не відповідає: пояснити, що це «прокидання» безкоштовного Render, показати скріни з `16-live-ui-screenshots/`.
- Помилка 400 при реєстрації з кирилицею з консолі curl: використовувати Swagger UI, не curl.
- Після демо прибрати за собою: видалити тестового користувача (крок 5 сценарію 2).
