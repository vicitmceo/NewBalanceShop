Repository

IRepository<T> → Repository<T>

Доступ до даних сховано за інтерфейсом у Domain.

public interface IProductRepository
  : IRepository<Product>
{ Task<List<Product>> GetByCategoryAsync(int id); }
Навіщо: сервіси не знають про EF Core; у юніт-тестах репозиторій підміняється Moq.

Dependency Injection

Program.cs

Усі залежності передаються через конструктор, реєстрація в одному місці.

builder.Services
 .AddScoped<IProductService, ProductService>();
Навіщо: слабка зв'язаність; в інтеграційних тестах підміняємо БД на InMemory.

Service Layer (Use Cases)

Application/Services

Бізнес-логіка в сервісах, контролер лише приймає й повертає HTTP.

OrderService.CreateAsync:
 перевірка складу, UnitPrice,
 TotalPrice, зменшення Stock
Навіщо: логіку можна тестувати без HTTP і без БД.

DTO + Mapper

Application/DTO, Mapping

API повертає DTO, а не сутності EF; мапінг у extension-методах.

public static CustomerDto ToDto(
  this Customer c) => new() { … };
Навіщо: PasswordHash ніколи не потрапляє у відповідь (є тест на це).

Middleware Pipeline

Program.cs

Запит проходить послідовність компонентів.

UseSwagger → UseCors
 → UseSession → MapControllers
Навіщо: CORS із cookie й сесія для кошика та логіну налаштовані централізовано.

Session State

CartController, AuthController

Кошик гостя й ID залогіненого покупця живуть у серверній сесії.

HttpContext.Session
 .SetInt32("customerId", id);
Навіщо: кошик не пишемо в БД до оформлення; логін без токенів.
